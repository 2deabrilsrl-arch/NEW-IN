ACTUALIZACIÓN A v12.1.0-REPORTES - REPORTES DIARIOS AUTOMÁTICOS
==========================================================================

Esta actualización agrega generación automática de reportes diarios con:
- Detalle de productos agregados por marca
- Productos encontrados vs no encontrados
- Un archivo por día para auditoría
- Limpieza automática semanal (mantiene últimos 7 días)

   copy newin_robot.py newin_robot_v12.0_BACKUP.py

2. Reemplazar con nueva versión:

==========================================================================
NUEVAS FUNCIONALIDADES
==========================================================================

1. REPORTES DIARIOS AUTOMÁTICOS
   
   Ubicación: C:\Users\santiago\NEW IN\logs\reportes_diarios\
   
   Cada ejecución diaria genera:
   REPORTE_DAILY_2026-02-02.txt
   REPORTE_DAILY_2026-02-03.txt
   ...

2. CONTENIDO DE CADA REPORTE
   
   - Fecha de ejecución
   - Resumen general:
     * Códigos madre procesados
     * Match rate (%)
     * Productos nuevos vs que ya estaban
   
   - Detalle por marca:
     * MK (MARCELA KOURY)
       - Cantidad: 5
       - Códigos: MK-10137, MK-5556, ...
     
     * T (TIENTO)
       - Cantidad: 12
       - Códigos: T-1100, T-1013, ...
   
   - Productos NO encontrados (si hay):
     * Lista de códigos que ingresaron en Dragonfish
       pero no están en Tiendanube todavía

3. LIMPIEZA AUTOMÁTICA
   
   El refresh semanal (lunes 17:55) elimina reportes >7 días.
   
   Resultado: Siempre tenés los últimos 7 días disponibles
              para auditoría y cotejo.

==========================================================================
EJEMPLO DE USO
==========================================================================

SITUACIÓN:
El viernes notás que falta un producto que debería estar en New In.

DIAGNÓSTICO:
1. Ir a: C:\Users\santiago\NEW IN\logs\reportes_diarios\

2. Abrir: REPORTE_DAILY_2026-01-30.txt (jueves)

3. Buscar el código del producto:
   
   Si está en "PRODUCTOS AGREGADOS" → Se procesó correctamente
   Si está en "PRODUCTOS NO ENCONTRADOS" → No está en TN todavía
   Si NO aparece → No ingresó en Dragonfish con motivo ING

4. Cotejar con Dragonfish para confirmar.

==========================================================================
DIFERENCIAS CON EL LOG TÉCNICO (daily.log)
==========================================================================

daily.log:
- Log técnico continuo
- Todas las ejecuciones en un solo archivo
- Detalles de API calls, errores, debugging
- Para desarrolladores/troubleshooting

reportes_diarios/:
- Un archivo por día
- Formato legible para humanos
- Organizado por marca
- Para auditoría de negocio
- Para cotejo con Dragonfish

==========================================================================
AUTOMATIZACIÓN
==========================================================================

NO REQUIERE CONFIGURACIÓN ADICIONAL

Las tareas ya configuradas se encargan de todo:

- NewInDaily (18:00 diario):
  * Procesa productos
  * Genera reporte del día
  * Guarda en reportes_diarios/

- NewInWeeklyRefresh (lunes 17:55):
  * Limpia New In
  * Elimina reportes >7 días
  * Mantiene última semana

==========================================================================
PREGUNTAS FRECUENTES
==========================================================================

P: ¿Los reportes ocupan mucho espacio?
R: No, ~2-5 KB por día, ~35 KB por semana máximo.

P: ¿Puedo cambiar cuántos días mantener?
R: Sí, en el código cambiá: limpiar_reportes_viejos(dias_mantener=7)
   Por ejemplo, dias_mantener=14 para 2 semanas.

P: ¿Qué pasa si elimino reportes manualmente?
R: Nada, el robot genera uno nuevo cada día. No afecta operación.

P: ¿Puedo ver reportes de hace más de 7 días?
R: Después del refresh semanal se eliminan. Si querés conservar alguno,
   copialo a otra carpeta antes del lunes.

P: ¿Los reportes afectan el rendimiento?
R: No, se generan en ~0.1 segundos al final de cada ejecución.
